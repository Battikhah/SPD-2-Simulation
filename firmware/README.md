# Firmware: streaming log-mel front end and ESP32 example

Status (1 November 2026): host parity verified with MSVC; **not built or run on an ESP32**. No ESP-IDF toolchain or board was available on the development PC, so on-board arena, latency, energy and flash use are unmeasured.

## `logmel/` — portable C99 front end

`logmel.c/.h` reproduces the training log-mel exactly as `scripts/grouped_cv_campaign.py` computes it: 8 kHz int16 PCM ÷ 32768, periodic Hann 512 (`np.hanning(513)[:-1]`), 59 frames at hop 128 per 8000-sample window, |FFT|² / 512, 64 HTK mel bands, natural log floored at 1e-10, then int8 quantisation `round_half_even(x / scale + zero_point)` with the model's input scale and zero point. `logmel_tables.h` is generated by `scripts/gen_logmel_tables.py` from the Python `WINDOW`/`MEL64` arrays, so the coefficients are the training values rounded once to float32. The 512-point radix-2 FFT has no dependency. On the ESP32, esp-dsp `dsps_fft2r_fc32` or a real-input FFT could replace it, but parity must then be re-checked.

Streaming: `logmel_push()` takes PCM in any chunk size and computes each frame once its 512 samples have arrived. It stops at each 1 s boundary so the caller can run inference. There is no 1 s or 10 s audio buffer.

| Memory | Bytes |
| --- | ---: |
| Static state `logmel_stream_t` (512-sample ring 1,024 + FFT scratch 4,096 + power row 1,028 + fields) | 6,184 |
| int8 output (59 × 64), written straight into the TFLM input tensor (inside the arena) | 3,776 |
| Optional float output (parity/debug only) | 15,104 |
| Constant tables in flash (window 2,048 + twiddles 2,048 + 501 mel weights 2,004 + band indices 384) | ≈6,500 |

The log uses `log()` (double) to match NumPy; `logf()` is a possible speed-up that needs a parity re-check.

### Host parity test (MSVC)

```powershell
.\.venv\Scripts\python.exe scripts\logmel_parity_fixtures.py   # development clips only
firmware\logmel\test\build_msvc.cmd
.\outputs\logmel-parity\parity_test.exe outputs\logmel-parity\fixtures.bin
```

Result: 18 windows (16 real 1 s windows from 8 development clips in folders 24, 25, 7, 8, 26, 27, 28 and 30, plus silence and a full-scale 440 Hz tone), streamed in uneven chunks. All 16 real windows give int8 inputs identical to Python, with maximum float error 1.1e-5. The full-scale tone has 42 of 3,776 values 1 LSB off, from float32 FFT error in quiet bins next to a very loud tone; the double build reduces this to 5. Overall 0.062% of int8 values differ and none by more than 1 LSB. Max absolute float error is 2.9e-2 (tone) and the mean is 5.8e-5.

## `esp32_stream1s/` — ESP-IDF example (unbuilt)

This example is derived from the ML-for-Senior benchmark harness (`deployment/esp32`, esp-tflite-micro 1.3.5, ESP-IDF 5.3–6.0). It streams a real 1 s fixture ten times, in 160-sample chunks, through `logmel_push` directly into the int8 input tensor. It runs `stream1s_w8` on each window and averages ten probabilities into one 10 s score. It reports a JSON line with the input checksum check, the fixture output delta, per-window front-end and inference time, `arena_used_bytes` and heap. It deliberately applies no decision threshold, because no final model or threshold has been frozen; it also uses one fold model (seed 0, fold 0), not the 3-seed ensemble.

```powershell
outputs\tf-venv\Scripts\python.exe scripts\gen_esp32_example.py   # fills main/generated (git-ignored)
cd firmware\esp32_stream1s
idf.py set-target esp32
idf.py build size
idf.py -p <PORT> flash monitor
```

### Embedding the 2 November recommendation

`docs/ESP32_DEV_DAY_REPORT.md` recommends stream1s_w8_d4, folder-balanced, with a threshold calibrated per device on known-healthy trees. To embed it instead of stream1s_w8:

```powershell
outputs\tf-venv\Scripts\python.exe scripts\gen_esp32_example.py --model outputs\esp32-tflm\full-stream1s_w8_d4-pb2.0-lorO-bal0.5\stream1s_w8_d4\model_int8.tflite
```

- The model is 35,344 B, with a 37 KiB arena lower bound, so it fits the 64 KiB `kArenaSize`.
- It uses the same 7 ops.
- Its input quantisation is slightly different (scale 0.09458, zero point 115). The generator requantises the fixture and the device reads the scale from the tensor.
- It is still a single fold model (recorder fold 0), not a model fitted on all development data.

**Calibration.** In the field, run the device on known-healthy trees first, then set the alarm threshold at the 90th percentile of their 10 s scores. Thresholds from other recorders flag everything on some devices.

Only a successful build and board run can establish operator support, arena allocation, latency, energy and flash/RAM fit. The complete sensing application also needs I2S/ADC capture, power management and LoRa buffers.
